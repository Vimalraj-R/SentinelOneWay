# Simulation Lab - Safe Detection Pipeline Demonstration

## Overview

The Simulation Lab provides a **safe, controlled environment** for demonstrating and testing SentinelOneWay's detection pipeline using **synthetic traffic data**. Perfect for judges, security analysts, and demonstrations.

**CRITICAL: No actual malicious packets are transmitted over the network.**

All traffic is generated synthetically in-memory and processed through the same detection pipeline as real network flows.

## Features

### 🎭 6 Attack Scenarios

1. **Normal Traffic** (Green)
   - Benign HTTP, DNS, and application traffic
   - Risk Level: Low
   - Use case: Baseline validation

2. **SYN Flood Attack** (Red)
   - Volumetric DDoS with incomplete TCP handshakes
   - Risk Level: Critical
   - Demonstrates: Volume-based detection

3. **Port Scan** (Orange)
   - Systematic reconnaissance across multiple ports
   - Risk Level: High
   - Demonstrates: Reconnaissance detection

4. **C2 Beaconing** (Red)
   - Periodic command-and-control communications
   - Risk Level: High
   - Demonstrates: Behavioral pattern detection

5. **DNS Tunneling** (Yellow)
   - Data exfiltration through DNS queries
   - Risk Level: Medium
   - Demonstrates: Protocol abuse detection

6. **Data Exfiltration** (Red)
   - Large outbound data transfer to external destination
   - Risk Level: Critical
   - Demonstrates: Exfiltration detection

### 🎚️ Intensity Control

**Slider: Low → Medium → High**

Affects:
- Traffic volume (flows per second)
- Attack characteristics (e.g., SYN/ACK ratios)
- Detection difficulty
- Risk scores

**Recommended Settings:**
- **Low (0.0-0.33)**: Subtle attacks, demonstrates sensitivity
- **Medium (0.34-0.66)**: Typical attack intensity
- **High (0.67-1.0)**: Obvious attacks, maximum impact

### ⏱️ Duration Control

**Options: 15s / 30s / 60s**

**Recommendations:**
- **15 seconds**: Quick demos, judge presentations
- **30 seconds**: Standard testing, default option
- **60 seconds**: Comprehensive demonstrations, correlation testing

### 📊 Live Metrics

**Real-time display shows:**

1. **Flows Generated**
   - Total synthetic flows created
   - Updates every second
   - Typical: 50-500 flows depending on intensity

2. **Threats Detected**
   - Alerts generated by detection pipeline
   - Shows detection effectiveness
   - Non-normal scenarios: ~1% of flows trigger alerts

3. **Avg Detection Latency**
   - Time from flow generation to threat classification
   - Typical: 5-8ms per flow
   - Shows pipeline performance

4. **Current Risk Score**
   - Real-time network risk assessment (0-100)
   - Calculated from scenario + intensity
   - Color-coded: Green → Yellow → Red

### 🔴 Simulation Mode Banner

**Prominent yellow banner displays:**
```
⚠️ Simulation Mode — Synthetic Traffic
All traffic is synthetically generated in-memory.
No actual malicious packets are transmitted over the network.
```

**Purpose:**
- Clear distinction from production monitoring
- Reassures judges/auditors about safety
- Legal/ethical compliance indicator

## API Endpoints

### Start Simulation

**POST** `/api/simulation/start`

```json
{
  "scenario": "syn_flood",
  "intensity": 0.8,
  "duration": 30
}
```

**Scenarios:**
- `normal` - Benign traffic
- `syn_flood` - SYN flood attack
- `port_scan` - Port scanning
- `c2_beacon` - C2 beaconing
- `dns_tunnel` - DNS tunneling
- `data_exfil` - Data exfiltration

**Response:**
```json
{
  "status": "running",
  "scenario": "syn_flood",
  "intensity": 0.8,
  "flows_generated": 0,
  "message": "Simulation started successfully"
}
```

### Stop Simulation

**POST** `/api/simulation/stop`

**Response:**
```json
{
  "status": "stopped",
  "flows_generated": 342,
  "duration_seconds": 30.5,
  "message": "Simulation stopped successfully"
}
```

### Get Metrics

**GET** `/api/simulation/metrics`

**Response:**
```json
{
  "flows_generated": 234,
  "threats_detected": 3,
  "avg_latency": 6.8,
  "current_risk": 92,
  "is_running": true,
  "scenario": "syn_flood",
  "intensity": 0.8
}
```

### Get Status

**GET** `/api/simulation/status`

**Response:**

## Integration with Detection Pipeline

**Flow Path:**
```
1. Simulation Lab UI (user clicks Start)
2. Backend generates synthetic FlowRecord objects
3. Feature Extractor processes flows
4. Hybrid Detection Engine runs:
   - Rule-based detectors
   - Random Forest classifier
   - Isolation Forest anomaly detector
5. Alerts created and stored in database
6. WebSocket broadcasts alerts to dashboard
7. Incident correlation runs (if enabled)
8. Metrics updated in real-time
```

**Same Pipeline = Same Results**

The detection results in Simulation Lab are **identical** to what would be seen with real network traffic exhibiting the same characteristics.

## Troubleshooting

### Simulation doesn't start

**Problem:** Click Start but nothing happens

**Solution:**
- Check backend is running (`python main.py`)
- Check browser console for errors
- Verify API endpoint: `curl http://localhost:8000/api/simulation/status`

### Metrics not updating

**Problem:** Flow counter stuck at 0

**Solution:**
- Check simulation is actually running (green dot)
- Verify metrics endpoint: `curl http://localhost:8000/api/simulation/metrics`
- Check browser console for polling errors
- Refresh page and try again

### No alerts on dashboard

**Problem:** Simulation runs but no alerts appear

**Solution:**
- Verify non-normal scenario selected (not "Normal Traffic")
- Check intensity is not too low
- Navigate away and back to Overview dashboard
- Check `/api/alerts/` endpoint for alerts
- Verify detection pipeline is enabled

### Duration too short

**Problem:** Simulation ends before seeing results

**Solution:**
- Use 60-second duration for comprehensive testing
- Lower intensity for longer attack sequences
- Check alerts after simulation completes (they persist)
